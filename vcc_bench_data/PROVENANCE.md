# VCC-Bench Dataset Provenance

Resolves P1 issue "data: document dataset provenance và versioning".

## Raw vs. derived

| Kind | Files | Built by |
|---|---|---|
| **Raw** | `wikipedia_vi_raw.json` | `scripts/fetch_vietnamese_data.py` (fetches live from Wikimedia API) |
| **Derived** | `vcc_bench_agent_tool_calling.json`, `vcc_bench_cross_lingual.json`, `vcc_bench_long_document_qa.json`, `vcc_bench_multi_turn_conversation.json`, `vcc_bench_needle_in_haystack.json`, `vcc_bench_v1.json` (merge of the five task files) | `scripts/build_vcc_bench.py`, from `wikipedia_vi_raw.json` + embedded legal texts + generated synthetic templates |

`vcc_bench_v1.json` is the file the evaluation scripts (`run_benchmark.py`,
`run_ablation.py`) load by default; the five per-task files are the same
samples split out individually and are useful for running/inspecting a
single task in isolation.

## Sources, license, and snapshot date per file

### `wikipedia_vi_raw.json` (raw)

- **Source**: `vi.wikipedia.org` via the Wikimedia API (see `USER_AGENT` /
  `urllib.request` calls in `scripts/fetch_vietnamese_data.py`).
- **Topics fetched**: 25 Vietnamese-Wikipedia article titles covering
  history, economy, culture, education, law, health, technology, AI,
  climate, energy, physics, biology, literature, music, geography,
  government, agriculture, and transport — full list is the `WIKI_TOPICS`
  constant in `scripts/fetch_vietnamese_data.py`.
- **Snapshot date**: `2026-07-06` (the `date` field in the file's own
  `metadata` block — set at fetch time, not re-derived here).
- **Yield**: 15 articles / 393 paragraphs (`num_articles` /
  `num_paragraphs` in `metadata`; not every requested topic resolves to a
  usable article).
- **License**: CC BY-SA 4.0 (Wikipedia's standard content license).
- **Regenerate**: `python scripts/fetch_vietnamese_data.py` (hits the live
  Wikimedia API — re-running will not byte-for-byte reproduce this exact
  snapshot if the underlying Wikipedia articles have since been edited;
  see "Reproducibility caveat" below).

### Vietnamese legal texts (embedded, raw)

- **Source**: Vietnamese government legal documents (e.g. Hiến pháp 2013),
  embedded directly as literal Python data in
  `scripts/build_vcc_bench.py` (`VIETNAMESE_LEGAL_TEXTS`) rather than
  fetched at build time.
- **License**: Public domain (Vietnamese state legal/administrative
  documents are not subject to copyright under Vietnamese law).
- **Regenerate**: not applicable — this text is checked into
  `scripts/build_vcc_bench.py` itself, so it is exactly reproducible by
  construction; there is no separate raw file for it.

### Synthetic templates (agent tool-calling, cross-lingual, multi-turn,
### needle-in-haystack)

- **Source**: generated by `build_agent_tool_calling()`,
  `build_cross_lingual()`, `build_multi_turn_conversation()`, and
  `build_needle_in_haystack()` in `scripts/build_vcc_bench.py` — hand-written
  Vietnamese templates combined with `wikipedia_vi_raw.json` paragraphs
  (for needle-in-haystack "haystack" filler and long-document contexts).
- **License**: MIT (original, self-authored — no third-party source text
  beyond the Wikipedia/legal material folded in).
- **Determinism**: `random.seed(42)` is set at the top of
  `scripts/build_vcc_bench.py`, so sample selection/shuffling is
  reproducible given the same `wikipedia_vi_raw.json` input.

### `vcc_bench_v1.json` and the five per-task files (derived)

- **Version**: `1.0.0` (per-file `metadata.version`).
- **Snapshot date**: `2026-07-06` (`metadata.date`).
- **License**: `CC-BY-SA 4.0 (Wikipedia) + Public Domain (Legal) + MIT (synthetic)`
  — a union of the three source licenses above, since samples combine all
  three (see `metadata.license` in the file itself).
- **Built by**: `python scripts/build_vcc_bench.py`, which reads
  `wikipedia_vi_raw.json`, combines it with the embedded legal texts and
  synthetic templates, runs `validate_dataset()` (schema + basic quality
  checks), and writes the five task files plus the merged `vcc_bench_v1.json`.
- **Total samples**: 243 across 5 tasks (`metadata.total_samples`).

## Preprocessing, cleaning, deduplication

Handled inside `scripts/build_vcc_bench.py`:

- `build_paragraphs_by_length()` filters/buckets Wikipedia paragraphs by
  character length before they're used as contexts, so no near-empty or
  extremely short paragraphs make it into a sample.
- `validate_dataset()` runs schema validation (required fields present)
  and basic quality checks (non-empty context/query/reference_answer,
  `char_length` consistency) over the final sample set before it's
  written to disk — any sample failing validation is dropped, not
  silently kept.
- No explicit near-duplicate detection across paragraphs is performed
  beyond Wikipedia's own article-level deduplication; if this becomes a
  concern for a future dataset version, add it to
  `build_paragraphs_by_length()` before splitting.

## Train / validation / test split

**VCC-Bench v1 is a single fixed evaluation set — there is no train/val/test
split.** It is a benchmark, not training data: `run_benchmark.py` and
`run_ablation.py` evaluate every configured method against the full 243
samples. Individual samples do not carry a `split` field (see
`vncompress/config.py`'s `ExperimentConfig.split`, which is kept as
`"full"` — a placeholder should a future version introduce held-out splits
for e.g. hyperparameter tuning without leaking into the reported numbers).
Training scripts (`run_training.py`, `run_train_slm.py`) use their own
`--train-data-path` argument and do not draw from `vcc_bench_data/` by
default.

## Checksums

`CHECKSUMS.json` in this directory records the SHA-256 and byte size of
every dataset file, generated/verified with `scripts/checksum_datasets.py`:

```bash
python scripts/checksum_datasets.py            # verify current files against CHECKSUMS.json
python scripts/checksum_datasets.py --write    # regenerate CHECKSUMS.json after a dataset change
```

If you regenerate a dataset file (e.g. re-running `build_vcc_bench.py`
after editing a template), re-run `--write` and commit the updated
`CHECKSUMS.json` alongside it — a checksum mismatch means the file on disk
no longer matches what was last recorded as the canonical version.

## Reproducibility caveat

`wikipedia_vi_raw.json` is fetched live from Wikipedia; the checked-in copy
is the actual raw input the current `vcc_bench_v1.json` was built from, and
is itself version-controlled and checksummed specifically so that re-running
`build_vcc_bench.py` against *this* file reproduces the same derived
*samples* — do not re-run `fetch_vietnamese_data.py` expecting a
byte-identical result, since the live articles may have changed since the
snapshot date. Run `build_vcc_bench.py` against the `wikipedia_vi_raw.json`
already in this directory (the default), not a freshly re-fetched one.

**Verified (2026-08-17):** re-running `python scripts/build_vcc_bench.py`
against the checked-in `wikipedia_vi_raw.json` reproduces the exact same
243 samples (`random.seed(42)` makes selection/shuffling deterministic),
but **not** a byte-identical file — `metadata.date` is stamped with the
current date at build time, not the original snapshot date, so the file
hash changes on every regeneration even when the sample content doesn't.
If you regenerate for a real reason (not just to verify reproducibility),
run `python scripts/checksum_datasets.py --write` afterwards and commit the
updated `CHECKSUMS.json`; if you were just verifying reproducibility,
`git checkout -- vcc_bench_data/*.json` restores the previously-committed
files instead of keeping the re-stamped ones.
